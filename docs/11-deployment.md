# 11 — Deployment (GitHub → MongoDB Atlas → Render → Vercel)

Everything is prepared in the repo: `render.yaml` (API), `frontend/vercel.json` (frontend, API
rewrite, security headers) and `.github/workflows/ci.yml` (tests on every push). You need four free
accounts: **GitHub, Render, Vercel, Cloudinary** (plus optional Razorpay and Resend).

```
Browser ──▶ Vercel (React build + /api rewrite) ──▶ Render (FastAPI) ──▶ MongoDB Atlas
                                                         └──▶ Cloudinary (images), Razorpay, Resend
```

## 1. GitHub (private repository)

```bash
cd "/Applications/Resort Booking"
git config user.name "Your Name"
git config user.email "you@example.com"          # the email on your GitHub account
git log --format='%h %ae' | head                  # existing commits use your Mac's default email;
                                                  # optional fix (only before the first push):
# git rebase -r --root --exec "git commit --amend --no-edit --reset-author"
```

Create an empty **private** repo on github.com (no README/licence), then:

```bash
git remote add origin git@github.com:<you>/vistara-stays.git
git push -u origin main
```

`.env` files, `backend/media/`, `node_modules/` and virtualenvs are git-ignored. Check before the
first push: `git ls-files | grep -E '\.env$|media/'` must print nothing. CI runs automatically
(GitHub → Actions).

## 2. MongoDB Atlas (production database)

1. **Database Access → Add New Database User**: username `vistara_prod_app`, a long generated
   password, role **"Only read and write to specific database"** → `vistara_prod`. Don't reuse the
   development user (whose password has also been shared in chat — rotate it).
2. **Network Access**: Render's free tier has no fixed outbound IP, so add `0.0.0.0/0`. The
   database is then protected by the strong password + TLS only — keep the password secret, and
   prefer a paid Render plan with static IPs for real production.
3. **Connect → Drivers** → copy the `mongodb+srv://…` URI (URL-encode special characters).

## 3. Cloudinary (images — required in production)

Sign up at cloudinary.com → Dashboard → copy **Cloud name, API key, API secret**. The API refuses to
start in production without them (local disk storage would be wiped on every Render deploy).

## 4. Render (API)

1. Render → **New → Blueprint** → connect the GitHub repo. It reads `render.yaml`.
2. Fill the secret values it asks for:

| Variable | Value |
|---|---|
| `MONGODB_URI` | the production URI from step 2 |
| `CORS_ORIGINS` | `https://<your-app>.vercel.app` (set after step 5; comma-separate extra domains) |
| `FRONTEND_URL` | same as above |
| `PUBLIC_API_URL` | `https://<service>.onrender.com` |
| `CLOUDINARY_*` | from step 3 |
| `RAZORPAY_*`, `RESEND_API_KEY` | leave empty for now (see §7) |

`JWT_SECRET` is generated by Render. `APP_ENV=production`, `COOKIE_SECURE=true` and
`PAYMENT_PROVIDER=simulated` come from the blueprint.

3. Deploy, then check `https://<service>.onrender.com/api/v1/health` → `{"status":"ok"}` and
   `/api/v1/health/ready` → `"database":"ok"`. Indexes are created automatically at startup.

4. **Seed demo data and create your admin** (run from your Mac against the production database;
   `APP_ENV=development` here only relaxes the Cloudinary/cookie checks for the script):

```bash
cd backend && source .venv/bin/activate
export MONGODB_URI='<production URI>' MONGODB_DB=vistara_prod APP_ENV=development
export SEED_PASSWORD='<a new password for the sample accounts>'
python -m scripts.seed
printf '%s\n' '<admin password>' | python -m scripts.create_admin --email you@example.com --password-stdin
# Move destination photos from Wikimedia hotlinks to Cloudinary (needs the CLOUDINARY_* values):
export IMAGE_STORAGE=cloudinary CLOUDINARY_CLOUD_NAME=… CLOUDINARY_API_KEY=… CLOUDINARY_API_SECRET=…
python -m scripts.migrate_images_to_cloudinary
unset MONGODB_URI MONGODB_DB APP_ENV SEED_PASSWORD IMAGE_STORAGE CLOUDINARY_API_SECRET
```

## 5. Vercel (frontend)

1. Edit `frontend/vercel.json`: replace `YOUR-RENDER-SERVICE.onrender.com` with your Render host,
   commit and push.
2. Vercel → **Add New → Project** → import the repo → **Root Directory: `frontend`** (framework:
   Vite, build `npm run build`, output `dist` — detected automatically). No environment variables are
   needed: the browser calls `/api/...` on the Vercel domain and Vercel forwards it to Render, which
   keeps the refresh-token cookie first-party.
3. Deploy, then put the Vercel URL into Render's `CORS_ORIGINS` and `FRONTEND_URL` and redeploy the API.

## 6. Smoke test production

- [ ] Home page loads over HTTPS; DevTools → Console has no CSP errors.
- [ ] Sign up → the verification link appears in **Render → Logs** (console email) → verify.
- [ ] Book a sample resort with the simulated payment; cancel it.
- [ ] DevTools → Application → Cookies: `vs_refresh` is `HttpOnly`, `Secure`, `SameSite=Lax`.
- [ ] Log in as your admin → `/admin` works; a customer account gets “You don’t have access”.
- [ ] `/api/v1/health/ready` is `ok`; Render's health check is green.

## 7. Optional integrations

**Razorpay test mode** — dashboard.razorpay.com in **Test Mode** → API Keys → generate. Webhooks →
add `https://<your-app>.vercel.app/api/v1/payments/razorpay/webhook` with events
`payment.captured, payment.failed, refund.processed, refund.failed` and a secret. In Render set
`RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, `RAZORPAY_WEBHOOK_SECRET` and `PAYMENT_PROVIDER=razorpay`.
Pay with Razorpay's test cards; no real money moves in test mode.

**Resend (real emails)** — resend.com → verify a sending domain → API key. Set `EMAIL_BACKEND=resend`,
`RESEND_API_KEY`, and `EMAIL_FROM` with your verified domain.

## 8. Operations

**Free-tier behaviour.** Render's free service sleeps after ~15 minutes idle; the first request then
takes 30–60 s. Booking correctness doesn't depend on the background loop — expired holds and finished
stays are also handled lazily whenever they're read or booked.

**Logs.** Every request is one JSON line with `request_id`, method, path, status and duration. Error
responses include the same `request_id`, so a user's error can be matched to the exact log line.
Passwords, tokens and (in production) email bodies are never logged.

**Backups.** Atlas M0 has no automated backups. Take regular dumps and keep them encrypted and private:

```bash
mongodump --uri '<production URI>' --db vistara_prod --archive=vistara-$(date +%F).gz --gzip
mongorestore --uri '<target URI>' --archive=vistara-YYYY-MM-DD.gz --gzip --nsInclude 'vistara_prod.*'
```

For real operations, upgrade to a paid Atlas tier for continuous backups and point-in-time recovery.

**Troubleshooting**

| Symptom | Likely cause |
|---|---|
| Render deploy fails at startup with a settings error | A required production variable is missing (the message names it: `JWT_SECRET`, `COOKIE_SECURE`, `CLOUDINARY_*` …). |
| `/health/ready` → 503 | Wrong `MONGODB_URI`/password, or Atlas Network Access missing `0.0.0.0/0`. |
| Frontend loads but every API call fails | `vercel.json` still points at `YOUR-RENDER-SERVICE`, or the API is waking up (wait a minute). |
| Login works but you're logged out on reload (403 on `/auth/refresh`) | `CORS_ORIGINS`/`FRONTEND_URL` on Render don't exactly match the Vercel URL (no trailing slash). |
| Images missing in production | Run the Cloudinary migration (§4), or check `CLOUDINARY_*`. |
| CSP error in the console | A new third-party host must be added to the `Content-Security-Policy` in `vercel.json`. |
| 429 responses | Rate limits (e.g. 10 logins/minute per IP) — wait a minute. |
